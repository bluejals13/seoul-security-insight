# Core Rules (Always-On)

> **적용 시점 (Trigger)**: 모든 작업에서 항상 적용되는 최상위 핵심 아키텍처, 무결성 및 민감정보 보호 규칙  
> **적용 대상 (Scope)**: 프로젝트 전체 (`*`)

---

## 1. 프로젝트 개요 및 정체성
- **프로젝트명**: 서울쉴더스 (Seoul Shielders)
- **팀**: 4조 - 서울쉴더스 (손인선, 강대현, 황인찬, 이승혁, 전승호, 정예빈, 정세진)
- **주제**: 서울지역 보안 인프라 분석 및 지도 기반 치안 정보 서비스
- **목표**: 서울시 25개 자치구 전체의 치안/보안 인프라 상태를 한눈에 파악하고, 파출소, CCTV, 여성안심귀갓길, 안전시설 등을 지도 기반으로 확인할 수 있는 Streamlit 서비스 구축

---

## 2. 핵심 아키텍처 원칙
1. **계층 분리 체계 준수**:
   `데이터 수집 → Data Loader → Preprocessing → Analysis → Visualization → Page`
   - 실제 데이터/API와 UI(Streamlit)를 직접 결합하지 않는다.
   - `app.py`나 단일 파일에 모든 로직을 몰아넣지 않는다.
2. **기존 기능 보호 및 불필요한 리팩터링 금지**:
   - 기존 코드를 함부로 삭제하거나 전체 구조를 통째로 갈아엎지 않는다.
   - 작업 전 기존 코드와 인터페이스를 항상 먼저 확인하고 최소한의 범위 내에서만 수정한다.
   - 코드 수정 시 기존 기능의 회귀(Regression) 여부를 반드시 확인한다.
3. **Mock Data & 실제 데이터 하위 호환성**:
   - 프로토타입 단계로서 Mock Data가 기본 지원된다.
   - 실제 데이터가 없더라도 앱은 Mock Data로 항상 정상 실행되어야 한다.
   - 실제 데이터 추가 시 Data Loader 계층만 확장하여 기존 분석/시각화 로직을 그대로 재사용한다.

---

## 3. 민감정보 보호 및 절대 금지 규칙
1. **API Key 및 민감 자격 증명 보호**:
   - API Key, 비밀번호, 토큰 등은 코드 내 하드코딩을 절대 금지하며 `.env` 또는 Streamlit secrets를 활용한다.
   - 민감정보 파일은 Git에 절대 커밋하지 않는다.
2. **자율적 파괴적 행위 금지**:
   - 승인 없는 강제 커밋/푸시, 히스토리 삭제, 대규모 파일 삭제를 절대 금지한다.
